## مفهوم

**Cloaking** یعنی با **قصد دستکاری رتبه و گمراه کردن کاربر**، یک محتوا به موتور جست‌وجو و محتوای دیگری به آدم‌ها بدهی. نمونهٔ کلاسیکش این است که Googlebot مقالهٔ کامل و پر از عبارت ببیند، ولی کاربر وارد تبلیغ، ریدایرکت یا پیشنهاد کاملاً متفاوت شود.

هر تفاوتی cloaking نیست. ترجمه و بومی‌سازی، وضعیت consent، شخصی‌سازی کاربر لاگین‌شده، موجودی لحظه‌ای، دسترس‌پذیری و A/B test می‌توانند مشروع باشند؛ به شرط اینکه برای نیاز کاربر طراحی شده باشند، نه برای جدا کردن crawler. هدف اصلی صفحه باید ثابت بماند و برای زبان‌ها بهتر است URL پایدار و قابل crawl داشته باشی.

تشخیص user-agent به‌خودی‌خود اسپم نیست. مشکل از جایی شروع می‌شود که crawler نسخهٔ رتبه‌گیر بگیرد و کاربر مشابه به آن دسترسی نداشته باشد.

## چرا مهم است

Cloaking می‌تواند به افت الگوریتمی یا manual action برسد و هم‌زمان QA، امنیت و حقوقی را به دردسر بیندازد. عیب‌یابی هم سخت می‌شود، چون تیم، crawler و مشتری هر کدام شاید خطای متفاوتی ببینند.

## پیاده‌سازی وردپرس

**Yoast SEO**

1. برای هر زبان پست عادی با canonical خودش و hreflang متقابل بساز؛ بدنه را برای user-agent crawler عوض نکن.
2. cache و افزونهٔ ترجمه را تست کن تا Googlebot نسخهٔ قدیمی یا دارای دسترسی ویژه نگیرد.

**Rank Math**

1. Redirection و کنترل نقش کاربری‌اش استثنای cloaking نیست. snippet عمومی باید با مقصد عمومی بخواند.
2. Schema و ادعای قابل دیدن را با هم بررسی کن؛ دادهٔ ساختاریافته باید چیزی را توصیف کند که کاربر می‌بیند.

**AIOSEO**

1. متغیرهای title و description پویا را با صفحهٔ عمومی هماهنگ نگه دار.
2. بعد از تغییر قانون personalization، cache صفحه و CDN را پاک کن و پاسخ ناشناس را مقایسه کن.

**SEOPress:** فقط وقتی Redirection یا اتصال چندزبانه‌اش مالک مسیر است تفاوت عملی دارد؛ آزمون برابری crawler و کاربر همان است.

**جا خالی واقعی:** افزونهٔ SEO نمی‌تواند CDN worker، موتور personalization، اسکریپت تبلیغ یا mu-plugin را برای branch مخصوص crawler بازرسی کند. لاگ سرور و مقایسهٔ پاسخ لازم است.

## پیاده‌سازی Next.js

در Next.js 16 قرارداد `proxy.ts` جای `middleware.ts` را گرفته و middleware deprecated است. زبان را با URL مدیریت کن و حق انتخاب بده:

```ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl;

  if (pathname === "/") {
    return NextResponse.redirect(new URL("/fa", request.url));
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/((?!api|_next/static|_next/image|favicon.ico).*)"],
};
```

صفحه‌های زبان را روی `/en/...` و `/fa/...` پایدار نگه دار. بخش حساب را با وضعیت احراز هویت شخصی کن، ولی ادعا و محتوای اصلی عمومی برای کاربر ناشناس و crawler یکی باشد.

یادداشت Pages Router: همین قاعده در `getServerSideProps` و middleware قدیمی برقرار است. با `user-agent` برای Googlebot تیتر یا پیشنهاد اضافه تولید نکن.

## اشتباه‌های رایج و افسانه‌های منسوخ

- **DEPRECATED:** «Dynamic rendering مجوز دائمی برای محتوای متفاوت bot است.»
- **DEPRECATED:** «اگر Googlebot واقعی بود، هر پاسخ متفاوتی مجاز است.»
- **DEPRECATED:** «Geo-redirect اجباری crawlerها سئوی بین‌المللی را بهتر می‌کند.»
- قاطی کردن login wall یا محدودیت قانونی مشروع با cloaking، بدون اینکه صفحهٔ توضیح عمومی صادق داشته باشی.
- A/B testی که فقط برای crawler هدف اصلی صفحه را عوض می‌کند.
- تست فقط در مرورگر و بی‌خیال شدن از پاسخ خام سرور.

## نکته‌های سطح بالا / پروداکشن

برای variationها رجیستر داشته باش: مالک، مخاطب، دلیل، component، کلید cache و تاریخ انقضا. Cache poisoning تصادفی ممکن است از بیرون دقیقاً شبیه cloaking دیده شود.

در تشخیص، محتوای اصلی رندرشده، status، زنجیرهٔ ریدایرکت، canonical، robots، schema و لینک‌ها را بین fetch معتبر crawler و درخواست ناشناس مقایسه کن. دستور fingerprint و دور زدن تشخیص منتشر نکن؛ راه‌حل حذف branch مخصوص crawler است.

اگر هکر cloaking تزریق کرده، نفوذ را مهار کن، قانون مخرب سرور/CDN را بردار، credential را بچرخان و همهٔ نسخه‌ها را تست کن. Security Issues و Manual Actions در GSC را ببین و زمان ثابت برای برگشت قول نده.
