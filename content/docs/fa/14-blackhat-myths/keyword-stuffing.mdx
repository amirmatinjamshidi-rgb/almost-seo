## مفهوم

**Keyword stuffing** یعنی صفحه را با کلمه، عدد یا واریانت‌های یک کوئری پر کنی تا رتبه را دستکاری کنی؛ طوری که متن غیرطبیعی یا بی‌ربط شود. تکرار زورکی در عنوان، H1، بدنه، alt تصویر، انکر لینک و فهرست بلند شهر یا شماره تلفن هم جزو همین الگوست.

استفاده از عبارت اصلی جایی که به خواننده کمک می‌کند stuffing نیست. جدول مشخصات واقعی، دایرکتوری شعبه‌های موجود و مترادف‌های طبیعی هم مشکلی ندارند. سؤال ساده این است: هر بار تکرار چیزی به کاربر می‌گوید، یا فقط برای سبز شدن یک چراغ افزونه آنجاست؟

گوگل درصد امنی برای «چگالی کلمه» اعلام نکرده. زبان را نمی‌شود با یک فرمول ثابت مدیریت کرد.

## چرا مهم است

متن پر از تکرار قبل از هر اتفاق سئویی، اعتماد و تبدیل را خراب می‌کند. از طرف دیگر می‌تواند وارد محدودهٔ سیاست اسپم شود. خطر بزرگ‌تر در قالب‌هاست: یک فرمول بد عنوان یا توضیح محصول ممکن است روی هزاران URL تکثیر شود.

<CorrectExample title="درست">

```html
<title>کفش تریل رانینگ؛ راهنمای انتخاب گریپ، فیت و زمین | نورث‌استار</title>

```

## پیاده‌سازی وردپرس

**Yoast SEO**

1. Focus keyphrase و تحلیل خوانایی را یادآور تحریریه ببین، نه شرط قبولی در گوگل.
2. برای سبز کردن چراغ، همهٔ واریانت‌ها را در عنوان و پاراگراف اول نچپان.

**Rank Math**

1. اگر صفحه طبیعی و کامل است، امتیاز پایین keyword density دلیل بازنویسی زورکی نیست.
2. قالب Titles & Meta محصول و لوکیشن را نمونه‌برداری کن تا عبارت تکراری سایت‌واید نباشد.

**AIOSEO**

1. پیشنهادهای TruSEO را برای بازبینی استفاده کن؛ بلوک «کلمات مرتبط» به انتهای صفحه نچسبان.
2. alt هر تصویر باید خود تصویر را توضیح بدهد، نه اینکه focus phrase را کپی کند.

**جا خالی واقعی:** هیچ‌کدام نمی‌فهمند تکرار در بافت متن مفید است یا نه. ویراستار انسانی، نمونه‌برداری از خروجی قالب و نگاشت intent به صفحه این فاصله را پر می‌کند.

## پیاده‌سازی Next.js

متادیتا و متن را از موضوع واقعی صفحه بساز، نه از آرایهٔ واریانت‌های کوئری:

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "کفش تریل رانینگ؛ راهنمای گریپ، فیت و زمین",
  description:
    "گریپ، ضربه‌گیری، ضدآب بودن و فیت کفش تریل را با یادداشت‌های تست میدانی مقایسه کن.",
};

export default function TrailShoesPage() {
  return (
    <main>
      <h1>کفش تریل رانینگ</h1>
      <p>بر اساس زمین و فیت انتخاب کن، نه بر اساس درصد ساختگی کلمه.</p>
    </main>
  );
}
```

در App Router، `metadata` یا `generateMetadata` را از Server Component خروجی بده؛ هر دو را در یک سگمنت با هم export نکن. آرایهٔ keyword را به title، span مخفی یا همهٔ توضیحات محصول join نکن.

یادداشت Pages Router: عنوان و توضیح کوتاه را با `next/head` بساز. تولید واریانت در `getStaticProps` کار را مشروع نمی‌کند.

## اشتباه‌های رایج و افسانه‌های منسوخ

- **DEPRECATED:** «چگالی کلمه باید ۲ تا ۳ درصد باشد.»
- **DEPRECATED:** «همهٔ مترادف‌ها باید در title، H1، پاراگراف اول و هر H2 بیایند.»
- **DEPRECATED:** «Meta keywords هنوز به رتبهٔ گوگل کمک می‌کند.»
- پر کردن alt تصویر و انکر داخلی با exact match.
- گذاشتن لیست شهر، کدپستی یا تلفن بدون کارکرد دایرکتوری.
- تزریق عبارت دقیق با AI بعد از اینکه متن مفید تمام شده است.

## نکته‌های سطح بالا / پروداکشن

قالب را audit کن، نه فقط یک مقاله را. title، H1، مقدمه، alt و انکر چند URL نماینده را کنار هم بگذار؛ تکراری که از component مشترک می‌آید معمولاً از یک جملهٔ بد فراگیرتر است.

برای پاکسازی، اطلاعات واقعی را نگه دار، متن را برای کاربر بازنویسی کن، بلوک کوئری را حذف کن و اول قالب مولد را ببند. تاریخ ریکاوری قول نده. اگر manual action داری، تغییرها را مستند و درخواست بازبینی واقعی ارسال کن.

در کاتالوگ بزرگ، نام محصول و ویژگی‌ها طبیعی تکرار می‌شوند. ببین داده موجودی واقعی را توصیف می‌کند و هر URL کار جدا دارد یا نه؛ شمارش خام کلمه به‌تنهایی شاهد خوبی نیست.
