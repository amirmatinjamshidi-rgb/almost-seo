## مفهوم

نظر روی گوگل (و سطح دیگر) **محتوای کاربر** دربارهٔ آن مکان است. روی تبدیل اثر می‌گذارد و به prominence غذا می‌دهد. فیلدی نیست که در وردپرس تایپ کنی.

سیاست نظر گوگل (راهنمای فعلی Business Profile / Maps) ممنوع می‌کند:

- نظر جعلی، از جمله آن‌هایی که خودت می‌نویسی، می‌خری، یا عوض می‌کنی.
- نظر **مشوق‌دار** (تخفیف در برابر ستاره) جایی که سیاست اجازه‌اش را نمی‌دهد.
- gating: «فقط مشتری خوشحال لینک گوگل بگیرد؛ ناراضی فرم.»
- نظر گذاشتن برای کسب‌وکار خودت یا فشار به نیرو که listing را پر کند.

مجاز: از مشتری‌ای که **از قبل تعامل داشته** بخواه بازخورد بگذارد، به فرم نظر لینک بده بدون فیلتر احساس، در جمع جواب بده بدون تهدید یا چپاندن کلمه.

ستاره در schema (`AggregateRating`) باید سیستم نظر **دیدنی و واقعی** روی صفحه را منعکس کند. ۴.۹ جعلی در JSON-LD اسپم است.

## چرا مهم است

لوکیشن بدون نظر و رقیب با ردپای واقعی، حتی در فاصلهٔ برابر، کلیک را می‌بازد. جهش نظر خریداری‌شده می‌تواند listing را بیندازد. اعتبار ops به‌علاوهٔ سیاست است، نه نمرهٔ پلاگین.

## پیاده‌سازی وردپرس

**Yoast SEO**

1. Yoast نظر GBP را نمی‌کشد. `AggregateRating` جعلی را با پلاگین snippet پیست نکن.
2. اگر بلوک testimonial داری، کپی آن‌پیج است، نه نظر گوگل مپ.

**Rank Math**

1. schema Rank Math ← نظر / امتیاز: فقط اگر قالب آن نظرها را **نشان می‌دهد**. امتیاز JSON-LD مخفی الگوی کلاسیک اسپم rich-result است.
2. ماژول «FAQ / review» Rank Math روی صفحهٔ لوکیشن جایگزین GBP نیست.

**AIOSEO**

1. فیلد امتیاز Local / schema در AIOSEO: همان قانون — دیدنی یا حذف.
2. schema نظر سایت‌واید از پیش‌فرض ۵ ستارهٔ الکی روشن نکن.

**جا خالی واقعی:** بعضی پلاگین اسلایدر نظر وردپرس از آیتمی که تایپ کردی `AggregateRating` می‌دهند. Yoast/Rank Math/AIOSEO/SEOPress هرچه وارد کنی را serialize می‌کنند. هیچ‌کدام در مقابل گوگل verify نمی‌کنند. جا خالی سیاست است، نه UI.

## پیاده‌سازی کد

```ts
export const locationJsonLd = {
  "@context": "https://schema.org",
  "@type": "CafeOrCoffeeShop",
  name: "Example Labs Café",
  url: "https://www.example.com/locations/example-st",
  telephone: "+982155550101",
  // omit aggregateRating unless reviews render in HTML
};

export function ReviewAsk() {
  return (
    <p>
      <a href="https://search.google.com/local/writereview?placeid=YOUR_PLACE_ID">
        Review us on Google
      </a>
    </p>
  );
}
```

App Router: Place ID از GBP، نه حدس. Pages Router: همان لینک، سرور-رندر. بعد از تشخیص ستارهٔ پایین href را در `useEffect` عوض نکن (gating).

هرگز API «خرید نظر» نخوان. اگر نظر first-party نشان می‌دهی، در DB با تاریخ نگه دار و HTML + JSON-LD مطابق رندر کن.

## اشتباه‌های رایج و افسانه‌های منسوخ

- **DEPRECATED:** «نظر بیشتر همیشه تو را شمارهٔ ۱ پک می‌کند» به‌عنوان اهرم تنها (فاصله و ربط هنوز هستند).
- **DEPRECATED:** فیلتر مشتری ناراضی به فرم گوگل و خوشحال به Maps.
- keyword stuffing در پاسخ مالک (`best plumber Vanak`).
- خرید نظر در تلگرام / سایت فریلنسر.
- کپی متن نظر رقیب.
- ستارهٔ schema بدون نظر روی صفحه.

## نکته‌های سطح بالا / پروداکشن

فرآیند: نیرو را برای **کی** پرسیدن (بعد از خدمت) آموزش بده، نه سهمیهٔ اسکرین‌شات پنج‌ستاره. escalation به آدم می‌رود، نه به جواب «گزارشت می‌کنیم» روی Maps.

چندلوکیشن: هر Place ID نظر خودش را دارد. نقل قول شعبهٔ A را روی شعبهٔ B نچسبان.

حقوقی: توهین و takedown مسیر خودشان را دارند؛ وقتی نظر واقعاً سیاست را می‌شکند در GBP گزارش جعل بده، نه وقتی فقط ۲ ستاره است.

لوکال YMYL (کلینیک، وکیل): نظر مشوق‌دار رادیواکتیوتر است.
