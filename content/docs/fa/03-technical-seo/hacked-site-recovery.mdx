## مفهوم

سایت هک‌شده در Search معمولاً یعنی: صفحات اسپم ایندکس‌شده (`/cheap-viagra` روی هاست تو)، لینک/متن مخفی تزریقی، **cloaking** (Googlebot اسپم می‌بیند، کاربر سایت واقعی)، یا interstitial فیشینگ. Security Issues / اقدام دستی در GSC ممکن است از قبل باز باشد.

بازیابی **اول امنیت** است، بعد SEO:

1. سوراخ را ببند (پچ CMS، چرخاندن راز، کشتن webshell).
2. سرو اسپم را قطع کن (حذف فایل، ردیف DB، cron غیرمنتظره، ادمین اضافه).
3. به گوگل بگو آشغال رفته: آن URLها `404`/`410`، **به هوم‌پیج 301 نکن**.
4. وقتی سایت واقعاً تمیز است در GSC درخواست بازبینی بده.
5. لاگ را برای عفونت مجدد نگاه کن.

مشکل «disavow URL اسپم» نیست. آن URLها **هاست تو** هستند. Disavow برای لینک ورودی است که کنترل نمی‌کنی.

## چرا مهم است

اسپم زنده گوگل را یاد می‌دهد هاست ژنراتور اسپم است. ریدایرکت اسپم به صفحهٔ پول‌ساز می‌تواند شبیه doorway باشد. تمیز کردن بدون بستن سوراخ یعنی هر ماه همین کار.

<CorrectExample title="درست">
پاسخ حادثه: snapshot، پچ، چرخاندن کلید، grep درخت عمومی برای PHP/JS ناشناخته، دامپ پست جدید در WP، دامپ بازنویسی `.htaccess` که تو ننوشتی. URL اسپم **410** برمی‌گرداند. sitemap از URL مطمئن دوباره ساخته شده. GSC Security Issues ← درخواست بازبینی با یادداشت کوتاه واقعی. کاربر به سایت HTTPS واقعی با گواهی معتبر می‌خورد.

## پیاده‌سازی وردپرس

**Yoast SEO**

1. Yoast webshell نمی‌فهمد. Wordfence / اسکن بدافزار هاست / داک بازیابی رسمی WP.
2. بعد از پاکسازی sitemap را دوباره بساز تا پست اسپم از XML برود.
3. اگر پست اسپم `publish` بود، trash کن و permalink را 410 بگذار.

**Rank Math**

1. Instant Indexing ابزار بدافزار نیست. هزاران URL اسپم را ping نکن.
2. Redirects: مسیر اسپم را 410 کن؛ `.*` را regex-301 به خانه نکن.

**AIOSEO**

1. همان rebuild sitemap.
2. «submit همهٔ URL» را تا درخت تمیز است نادیده بگیر.

**جا خالی واقعی:** پلاگین امنیت ≠ پلاگین SEO. SEOPress جادوی بازیابی خاص ندارد. بازگردانی سطح هاست از بکاپ **پیش از هک** به‌علاوهٔ پچ ابزار واقعی است.

## پیاده‌سازی کد

```ts
import type { MetadataRoute } from "next";
import { getTrustedUrls } from "@/lib/content";

export default async function sitemap(): MetadataRoute.Sitemap {
  const urls = await getTrustedUrls();
  return urls.map((u) => ({ url: u, lastModified: new Date() }));
}
```

App Router: موجودی `app/` برای مسیر غیرمنتظره؛ `public/` برای HTML اسپم رهاشده؛ چرخاندن توکن env. `robots.ts` بعد از بازیابی نباید `Disallow: /` بماند — سایت تمیز را هم مخفی می‌کند.

لبه: قانون WAF بعد از فهمیدن بردار. Googlebot را برای همیشه به‌عنوان «امنیت» challenge نکن.

Pages Router: `pages/` و `public/` را همین‌طور چک کن.

هرگز لاگین «ادمین مخفی» در `/wp-login-secret` نفرست و اسمش را امنیت نگذار؛ پچ و 2FA.

## اشتباه‌های رایج و افسانه‌های منسوخ

- **DEPRECATED:** فایل Disavow برای URL اسپم **خودت**.
- **DEPRECATED:** منتظر «انقضای جریمه» بدون پاکسازی.
- **DEPRECATED:** دامنهٔ جدید به‌عنوان حرکت اول (برند را رها می‌کنی + فرآیند را پچ نمی‌کنی).
- 301 اسپم به هوم‌پیج.
- دوباره submit کردن sitemap که هنوز اسپم را لیست می‌کند.

## نکته‌های سطح بالا / پروداکشن

چک cloaking: هم با UA گوگل‌بات fetch کن **هم** به‌عنوان مرورگر از شبکهٔ دوم. اگر فرق دارند، فرض کن تمام نشده.

قالب doorway ژاپنی / داروخانه / کازینو روی فایل PHP تصادفی هنوز روی WP رهاشده رایج است. در GSC کوئری‌هایی را بگرد که هیچ‌وقت نباید رتبه بگیری.

فیشینگ حقوقی: هاست و Search باید صفحات را بردارند؛ صفحهٔ 410 برند کافی است.

خط زمانی را برای بازبینی GSC بنویس. بازبین مدرک بسته شدن سوراخ می‌خواهد، عذر شاعرانه نه.

اگر سایت اپ Next است، باز هم **origin** وردپرس (یا Strapi) هک‌شده را چک کن — هدلس URL اسپم را ناممکن نمی‌کند اگر CDN HTML تزریقی را کش کند.

## چطور مطمئن شوی

| ابزار | قبول | رد |
| --- | --- | --- |
| GSC Security Issues | بعد از بازبینی تمیز | هنوز لیست است |
| نمونه URL اسپم | 410/404 | 200 یا 301 خانه |
| URL Inspection روی URL پول‌ساز | محتوای واقعی، بدون لینک تزریقی | اسپم مخفی در HTML crawlشده |
| لاگ تازه | POST ناشناخته به shell نیست | فایل PHP جدید دوباره ظاهر می‌شود |
| سرچ `site:` | URL آشغال در حال افت | URL doorway جدید روزانه |
