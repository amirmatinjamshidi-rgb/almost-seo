## مفهوم

پلاگین SEO در وردپرس **control plane متادیتا** است: title، canonical، robots، XML sitemap، schema، breadcrumb و social metadata. استراتژی سئو، cache، CDN یا تضمین index شدن نیست.

فقط یک پلاگین را مالک اصلی خروجی کن. جدول زیر بر اساس مستندات محصول vendorها در سپتامبر ۲۰۲۶ است؛ بسته‌بندی مرتب عوض می‌شود، پس «پولی» ممکن است پلن Premium یا add-on جدا باشد.

| قابلیت | Yoast SEO | Rank Math | AIOSEO | SEOPress |
| --- | --- | --- | --- | --- |

«Lightweight» benchmark عمومی نیست. اثر واقعی به module روشن، hook قالب، اندازه DB، cron، object cache و retention لاگ 404 بستگی دارد.

## چرا مهم است

دو suite می‌توانند canonical متناقض، schema تکراری، sitemap رقیب و دو redirect engine بسازند. مهاجرت فقط به‌خاطر چراغ سبز content score ممکن است primary term، redirect یا schema metadata را جا بگذارد.

<CorrectExample title="درست">
یک پلاگین مالک title، canonical، robots، schema، social card، breadcrumb و sitemap است. Redirect یا همان‌جاست یا edge/server؛ نه هر دو. تیم tier، module خاموش، مالک داده و روش export/rollback را نوشته.
</CorrectExample>

```txt
Yoast: canonical + sitemap + schema
Rank Math: canonical + sitemap + 404 redirects

```

## پیاده‌سازی وردپرس

**Yoast:** گراف پیش‌فرض قوی و workflow آشنا؛ redirect و Local/WooCommerce تخصصی وابسته به محصول پولی. score آن ranking factor نیست.

**Rank Math:** UI ماژولار، redirect/404 monitor داخلی و کنترل schema زیاد. Analytics، Content AI و logging بی‌مالک را خاموش کن؛ امکانات پیشرفته و multi-location ممکن است PRO بخواهند.

**AIOSEO:** suite گسترده با sitemap، schema، breadcrumb، social، Local/WooCommerce و محصول redirect. قبل از قول به مشتری tier دقیق را ببین.

**جا خالی واقعی:** Yoast core مانیتور native برای requestهای 404 ندارد؛ Rank Math داخل پلاگین دارد؛ AIOSEO و SEOPress ابزار مشابه را به محصول پولی وصل می‌کنند. SEOPress وقتی فرق واقعی دارد که conditional schema، export redirect یا bundle جمع‌وجورتر PRO را لازم داری؛ نه اینکه چهارمین پلاگین نصبش کنی.

برای مهاجرت: backup فایل/DB، export پلاگین قدیم، import در staging، مقایسهٔ source، بعد deactivate—نه delete—تا پایان rollback window.

## پیاده‌سازی کد

برای پیدا کردن emitter تکراری در QA:

```js
const html = await fetch(process.env.QA_URL).then((response) => response.text());
const canonicals = html.match(/rel=["']canonical["']/gi) ?? [];
const jsonLdBlocks = html.match(/application\/ld\+json/gi) ?? [];

if (canonicals.length !== 1) throw new Error(`Expected one canonical, got ${canonicals.length}`);
console.log({ jsonLdBlocks: jsonLdBlocks.length });
```

چند JSON-LD block می‌تواند معتبر باشد؛ entity و `@id` را نگاه کن. ایراد ownership متناقض/تکراری است، نه صرفاً تعداد بیشتر از یک.

## اشتباه‌های رایج و افسانه‌های منسوخ

- **DEPRECATED:** «نمرهٔ ۱۰۰ پلاگین یعنی رتبه.»
- **DEPRECATED:** «schema plugin بیشتر یعنی rich result بیشتر.»
- مقایسهٔ قیمت دقیق یا screenshot قدیمی بعد از تغییر package.
- فعال کردن sitemap وردپرس core، پلاگین و CDN با هم.
- نگه داشتن بی‌نهایت لاگ 404 روی سایت bot-heavy.
- روشن کردن همهٔ moduleها چون پولشان را داده‌ای.

## نکته‌های سطح بالا / پروداکشن

ماتریس مالکیت بنویس: metadata، schema، redirect، sitemap، breadcrumb، social، analytics و retention 404. قبل/بعد نصب، TTFB سرد و گرم، query فرانت، latency ادیتور، cron و رشد table را اندازه بگیر. قابلیت Premium زیرساخت نیست؛ cache هاست و CDN جدا هستند.

این صفحه قیمت دقیق نمی‌دهد چون مالیات، promo، تعداد سایت و bundle عوض می‌شوند. release note و admin همان نسخهٔ نصب‌شده داور آخر است.
