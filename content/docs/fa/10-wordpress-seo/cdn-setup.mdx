## مفهوم

CDN محتوا را از edge نزدیک کاربر proxy یا serve می‌کند. asset استاتیک شروع کم‌ریسک است. full-page edge cache می‌تواند TTFB را کم کند، ولی cache key، bypass cookie، purge و رفتار origin باید صریح باشند. CDN canonical host را خودکار جابه‌جا نمی‌کند و PHP کندِ uncached را درمان نمی‌کند.

## چرا مهم است

تنظیم درست latency و load origin را کم می‌کند. تنظیم غلط می‌تواند asset host تکراری، cache شدن صفحه خصوصی، حذف query parameter، loop HTTPS، block شدن bot یا robots/canonical کهنه بعد release بسازد.

## پیاده‌سازی وردپرس

Cloudflare، Fastly، Bunny، Akamai و CDN هاست مدل purge/HTML متفاوت دارند. یک proxy/CDN اصلی داشته باش. `home` و `siteurl` وردپرس public HTTPS باشند؛ canonical را به hostname موقت CDN rewrite نکن.

**Yoast، Rank Math و AIOSEO:** بعد از تغییر metadata، sitemap، schema یا redirect cache را purge کن. canonical باید دامنهٔ عمومی سایت باشد. هیچ‌کدام DNS، certificate، WAF یا edge cache را برایت امن تنظیم نمی‌کنند.

**جا خالی واقعی:** SEO plugin مالک signal صفحه است؛ CDN/host مالک delivery. SEOPress اینجا استثنا نیست. purge API در cache plugin ثابت نمی‌کند login، preview، WooCommerce، REST و locale variation درست‌اند.

`/wp-admin/`، `/wp-login.php`، preview، authenticated session، cart، checkout، account، password reset و method ناامن را از HTML cache خارج کن.

## پیاده‌سازی کد

asset versioned می‌تواند immutable باشد؛ HTML محافظه‌کار:

```nginx
location ~* \.(?:css|js|woff2|png|jpg|jpeg|webp|avif|svg)$ {
    expires 1y;
    add_header Cache-Control "public, max-age=31536000, immutable";
}

location / {
    add_header Cache-Control "public, max-age=0, s-maxage=300, stale-while-revalidate=30";
    try_files $uri $uri/ /index.php?$args;
}
```

`immutable` فقط برای URL نسخه‌دار. در CDN با cookie سشن bypass کن و `Host`، scheme و client IP موردنیاز origin را درست پاس بده.

## اشتباه‌های رایج و افسانه‌های منسوخ

- **DEPRECATED:** «CDN خودکار رتبه را بالا می‌برد.»
- **DEPRECATED:** «چون CDN سریع است hostname آن را canonical کن.»
- cache طولانی 301/404 هنگام migration.
- انداختن query stringی که واقعاً resource را عوض می‌کند.
- block bot فقط با user-agent ادعایی.
- purge-all برای هر edit و ساختن origin stampede.

## نکته‌های سطح بالا / پروداکشن

DNS provider، مالک proxy، renewal certificate، auth origin، WAF exception، cache key، TTL matrix، purge API و emergency bypass را مستند کن. request ID edge/origin داشته باش. برای جلوگیری از cache poisoning، host را normalize، method/header عجیب را reject و variant واقعی را داخل key کن.
