## مفهوم

کوئری **short-tail** (رأس) پهن است: `espresso`، `سئو`، `بیمه`. رقابت بالا، نیت مخلوط، اغلب دست برند، دیکشنری، یا hub دسته.

کوئری **long-tail** مشخص است: `espresso machine for two-group café`، `noindex vs robots txt`. حجم per رشته کمتر، نیت روشن‌تر، اغلب همان کوئری که تبدیل می‌شود یا سایت متخصص واقعاً می‌تواند ببرد.

دم «چهار کلمه» نیست. **مشخص بودن** است. کوئری دوکلمه‌ای برند می‌تواند به‌اندازهٔ سؤال نه‌کلمه‌ای مشخص باشد.

«حجم» ابزار را رتبه‌بندی اهمیت ندان. GSC و ابزار آگهی نمونه می‌گیرند و گرد می‌کنند. دم با حجم صفر بعد از صفحهٔ درست هنوز در GSC ظاهر می‌شود. عبارت رأس اغلب با hubی که دم را هم می‌گیرد پوشش داده می‌شود، نه با صفحهٔ نازکی که فقط رأس را تکرار می‌کند.

## چرا مهم است

فقط دویدن دنبال رأس، سند عمومی می‌سازد که کسی نخواست. فقط دویدن دنبال دم ذره‌بینی، ۵۰۰۰ URL نزدیک-تکراری می‌سازد (doorway / thin). شغل **hub + URL پشتیبان** است، نه sort حجم در اکسل.

<CorrectExample title="درست">
Hub: `/guides/espresso-machines` رأس commercial و دم‌های مرتبط را در یک راهنمای منسجم می‌گیرد. بچه: `/guides/espresso-machines/plumbed-in-vs-tank` برای سؤال جدا.

```html
<!-- hub -->
<h1>Espresso machines</h1>
<p><a href="/guides/espresso-machines/plumbed-in-vs-tank">Plumbed-in vs tank</a></p>
```

لینک داخلی دم را دسترس‌پذیر می‌کند. بچه کپی spun از hub نیست.
</CorrectExample>

<IncorrectExample title="غلط" why="یک URL نازک per واریانت کلمه سایت را منفجر می‌کند و cannibal می‌سازد. CSV مرتب‌شده بر حجم، IA نیست.">
```txt
/best-espresso
/best-espresso-machine
/best-espresso-machines-2026
/espresso-machine-best
```

هرکدام ۳۰۰ کلمه از همان outline. ابزار گفت «همه حجم دارند.»
</IncorrectExample>

## پیاده‌سازی وردپرس

**Yoast SEO**

1. per ردیف اسپردشیت پست نساز. یک cornerstone (اصطلاح یواست) per hub، بعد پست پشتیبان واقعی.
2. لینک داخلی cornerstone فقط وقتی URL پشتیبان نیت جدا دارند مفید است.

**Rank Math**

1. «pillar» / focus keyword در Rank Math: یک رشتهٔ فوکوس per URL یادآوری است، قانون نیست. hub ممکن است برای خیلی کوئری مرتبط رتبه بگیرد.
2. پست را کلون نکن و سه کلمه عوض نکن تا دم دیگر را بزنی.

**AIOSEO**

1. فلگ سبک cornerstone در AIOSEO: همان یواست — hub را فلگ کن، دم را انبوه نساز.
2. آرشیو تگ برای هر مترادف دم معمولاً نباید hub ایندکس‌پذیر باشد.

**جا خالی واقعی:** پلاگین‌ها یک focus keyword نمره می‌دهند و آدم را به stuffing رأس می‌رانند. SEOPress همان فیلد فوکوس را دارد. هیچ‌کدام نمی‌گویند دو دم یک نیت‌اند.

## پیاده‌سازی کد

```ts
const routes = [
  { path: "/guides/espresso-machines", role: "hub" },
  { path: "/guides/espresso-machines/plumbed-in-vs-tank", role: "support" },
] as const;

export function isIndexableKeywordPage(role: "hub" | "support" | "variant") {
  return role !== "variant";
}
```

App Router: `generateStaticParams` از **خوشه**، نه از خروجی خام کلمه. Pages Router: همان. واریانت (`?kw=`) نباید ایندکس‌پذیر شود (duplicate ماژول ۰۳).

اگر باید آگهی را روی رأس فرود بیاوری، آن لندینگ می‌تواند باشد؛ باز کپی یکتا و استراتژی canonical می‌خواهد، نه ۵۰ کلون.

## اشتباه‌های رایج و افسانه‌های منسوخ

- **DEPRECATED:** «دم‌بلند همیشه تبدیل می‌شود؛ رأس هیچ‌وقت.» به کسب‌وکار بستگی دارد. رأس برند تبدیل می‌شود. سؤال چهارکلمه‌ای تصادفی اغلب نه.
- **DEPRECATED:** دامنهٔ exact-match برای هر دم.
- **DEPRECATED:** حداقل تعداد کلمه برای «رتبه گرفتن رأس.»
- نادیده گرفتن دم GSC که از قبل به URL موجود می‌خورد (شاید از قبل مال تو باشد).
- ترجمهٔ واژه‌به‌واژهٔ رأس انگلیسی به فارسی و انتظار همان SERP.

## نکته‌های سطح بالا / پروداکشن

از **GSC + زبان فروش + تیکت پشتیبانی** شروع کن، بعد شکاف را با ابزار شخص ثالث پر کن. ابزار کوئری اختراع می‌کند؛ مشتری نه.

برای فارسی، صرف و فرم محاوره (`سئو سایت` در مقابل `بهینه‌سازی موتور جستجو`) اغلب یک خوشه‌اند، نه دو دم. به URL رقیب شکان‌شان نده.

رأس خبر و YMYL برای سایت جدید معمولاً بردنی نیست. دم متخصص را ببر، بعد hub را دربیاور.

## چطور مطمئن شوی

| ابزار | قبول | رد |
| --- | --- | --- |
| موجودی URL در مقابل شیت | یک URL per شغل جدا | یک URL per مترادف |
| GSC | hub کوئری مرتبط را جمع می‌کند | ۱۲ URL یک کوئری را تکه می‌کنند |
| بچه در مقابل والد | H1 و بخش یکتا | duplicate spun |
| ایندکس | واریانت noindex/canonical | ۵۰۰۰ دم نازک ایندکس‌شده |
