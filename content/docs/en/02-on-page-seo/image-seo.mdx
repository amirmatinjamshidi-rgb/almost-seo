## Concept

Images are content. **SEO** here is: crawlable files, honest **alt**, stable URLs, sane weight (CWV / LCP — Module 03), and optional image sitemap if images are first-class.

`alt` describes the image for people who cannot see it. If the image is decorative, empty `alt=""` is correct. If it is a screenshot of a `robots.txt` file, say that. Keyword stuffing in `alt` is hidden-text-adjacent.

Google Images uses the file, nearby text, title, and page. A unique image beats a stock photo shared by 10,000 posts. `loading="lazy"` on the LCP hero hurts LCP (Module 03).

SVG/CSS backgrounds are often invisible as “images” in Image Search. Real `<img>` or `next/image` with `src`.

## Why it matters

Missing alt is an a11y bug and a missed description. 4 MB PNGs as heroes blow LCP. Duplicate attachment URLs in WordPress clone the post.

<CorrectExample>
```html
<img
  src="/images/robots-txt-example.avif"
  width="1200"
  height="630"
  alt="Example robots.txt with Googlebot Allow and Disallow rules"
/>
```

File is compressed, dimensions set, alt is a sentence, not a keyword list.
</CorrectExample>

<IncorrectExample why="Empty meaningful images fail a11y. Stuffed alt and huge unnamed files waste crawl and LCP.">
```html
<img src="IMG_4032.PNG" alt="robots.txt robots txt SEO crawl budget Googlebot best">
```
</IncorrectExample>

## WordPress implementation

**Yoast SEO**

1. Yoast reads attachment alt from the media library. Fill it there. Do not index attachment pages unless they are real galleries (Search Appearance → Media).
2. Open Graph image: set a real 1200×630, not a 150 px avatar.

**Rank Math**

1. Rank Math image sitemap / alt suggestions: suggestions are not a substitute for looking at the picture.
2. “Alt from filename” automations turn `robots-txt-seo-googlebot.png` into stuffed alt.

**AIOSEO**

1. AIOSEO image SEO / sitemap. Exclude decorative icons.
2. WooCommerce: product image alt = what is in the frame, not `buy cheap {city}`.

**Feature gap:** Rank Math/AIOSEO/SEOPress push image sitemaps and bulk alt. Yoast is calmer. Bulk-from-filename is the common footgun.

## Code implementation

```tsx
import Image from "next/image";

export function Hero() {
  return (
    <Image
      src="/images/robots-txt-example.avif"
      alt="Example robots.txt with Googlebot Allow and Disallow rules"
      width={1200}
      height={630}
      priority
    />
  );
}
```

App Router: `priority` only on the LCP image. `remotePatterns` HTTPS only. Pages Router: same `next/image`. Decorative icons: `alt=""` or CSS.

Do not `next/image` an `http://` source on HTTPS pages (Module 03 mixed content).

## Common mistakes and outdated myths

- **DEPRECATED:** Keyword-stuffed filenames/alt as an Images ranking cheat.
- **DEPRECATED:** “All images must have long alt.” Decorative empty alt is correct.
- Lazy-loading the hero.
- Indexing `/attachment/img/` clones of the article.
- Hotlinking random CDNs that 403 Googlebot.

## Senior / production notes

Pipeline: upload → compress → unique filename → alt in CMS → dimensions. Designers dumping `export-final-v7.png` into `/public` without alt is the usual regression.

For diagrams, a short caption in HTML plus alt. For charts, the data should also exist as text or a table (a11y + extraction).

OG images (this site’s `opengraph-image` / `og` route) are social cards, not a replacement for in-article figures.
