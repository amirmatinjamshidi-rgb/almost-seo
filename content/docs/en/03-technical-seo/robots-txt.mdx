## Concept

`robots.txt` is fetched at the **host** root (`https://www.example.com/robots.txt`). It tells complying crawlers which paths they may **request**. It is not an access-control system and not a reliable deindexer.

Google’s robots.txt parser (the current spec, based on the IETF robots.txt standard) supports `User-agent`, `Allow`, `Disallow`, `Sitemap`. `Allow` / `Disallow` use prefix matching; longer / more specific rules can override. `Crawl-delay` is not a Googlebot directive.

If Googlebot is disallowed, it **will not fetch** the URL. It may still **index the URL** from a link, with little or no snippet. Use `noindex` (meta or `X-Robots-Tag`) on a crawlable URL when you want it out of the index.

`robots.txt` must be `200` with `text/plain`. A `404` robots.txt means “no restrictions.” A `503` robots.txt can pause crawling of the host.

## Why it matters

One leftover `Disallow: /` from staging is the fastest way to drop a site from Search. Conversely, failing to disallow crawl traps (admin, filters, infinite search) wastes budget and creates duplicates.

<CorrectExample>
```txt
# https://www.example.com/robots.txt
User-agent: Googlebot
Allow: /
Disallow: /api/
Disallow: /cart
Disallow: /checkout
Disallow: /*?*sort=

User-agent: *
Allow: /

Sitemap: https://www.example.com/sitemap.xml
```

Staging uses HTTP auth or a separate host whose robots.txt is `Disallow: /` **and** whose HTML is `noindex`. Production never copies that file.
</CorrectExample>

<IncorrectExample why="Googlebot cannot crawl, so noindex never runs; URLs may linger in the index as ghost listings.">
```txt
User-agent: *
Disallow: /

# plus every page also has <meta name="robots" content="noindex">
# which Googlebot will never see
```
</IncorrectExample>

## WordPress implementation

**Yoast SEO**

1. Yoast can write a virtual robots.txt (Tools → File editor) or you maintain a physical file. Do not run both with conflicting rules.
2. Yoast’s per-URL `noindex` is **not** robots.txt. Keep them straight.

**Rank Math**

1. Rank Math → General Settings → Edit robots.txt. Same conflict risk if Apache/nginx also serves a file.
2. Instant Indexing API is unrelated to robots.txt.

**AIOSEO**

1. Tools → Robots.txt. Preview the merged output before save.
2. AIOSEO “block search tools” style toggles can inject `Disallow` you did not intend — read the generated file.

**Feature gap:** All three will generate a robots.txt UI. None will stop you from shipping staging rules. SEOPress → Tools → robots.txt is the same class of editor. Always `curl` production.

## Code implementation

```ts
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  if (process.env.VERCEL_ENV !== "production") {
    return { rules: { userAgent: "*", disallow: "/" } };
  }

  return {
    rules: [
      {
        userAgent: "Googlebot",
        allow: "/",
        disallow: ["/api/", "/cart", "/checkout"],
      },
      { userAgent: "*", allow: "/" },
    ],
    sitemap: "https://www.example.com/sitemap.xml",
  };
}
```

App Router `app/robots.ts` wins over `public/robots.txt` if both exist — keep one. Pages Router: static `public/robots.txt`. Never block `/_next/static` or CSS/JS Google needs to render.

## Common mistakes and outdated myths

- **DEPRECATED:** robots.txt as a security boundary. Secrets in “disallowed” folders still leak if linked.
- **DEPRECATED:** `Crawl-delay` for Googlebot.
- **DEPRECATED:** Disallow = remove from index.
- Blocking `/wp-json/` thinking it hides content; it does not replace `noindex` on thin archives.
- Wildcard mistakes: `Disallow: /tmp` also blocks `/tmp-offers` depending on prefix rules — test with Google’s robots.txt tester / Inspector.

## Senior / production notes

Multi-subdomain brands need a robots.txt **per host**. `cdn.example.com` and `www.example.com` do not share a file.

At scale, generate robots.txt from the same allowlist as the edge WAF so marketing cannot disallow `/blog` in one place and allow it in another.

Google-Extended and other AI crawlers have their own tokens. Blocking them is a product decision, not an SEO ranking lever for Google Search. Do not copy a “block all bots except Googlebot” gist that also blocks Google-inspection tools you need.

## How to verify

| Check | Pass | Fail |
| --- | --- | --- |
| `curl -I https://www.example.com/robots.txt` | `200`, `text/plain` | `404` you thought was restrictive; `503` stuck |
| GSC robots.txt report / URL Inspection | Allowed for money URLs | “Blocked by robots.txt” on articles |
| Live vs staging | Staging disallows; prod allows | Prod is the staging file |
| Rich Results / Inspector fetch | CSS/JS not blocked | Page half-renders |
